Respostas às questões de interpretação

1 Por que o container antigo não mudou ao editar index.html?

O COPY colocou uma cópia do arquivo na imagem durante o build. O web-v1 usa essa imagem, sem compartilhar a pasta local por volume. Editar o arquivo não atualiza a cópia existente; é preciso construir outra imagem e criar um container com ela.

2 Qual a função de docker history?

Mostrar o histórico de criação da imagem, incluindo instruções e tamanhos associados às entradas. Assim podemos localizar COPY e etapas da imagem base. Não é o log do servidor nem um mapa exato de todos os arquivos ou camadas físicas.

3 Por que parar o antigo antes de usar a mesma porta 8080?

O web-v1 ocupa a publicação da porta TCP 8080 do ambiente. Outro container não pode usar a mesma combinação de endereço, porta e protocolo ao mesmo tempo. O stop libera a porta; o rm remove o container parado, sem apagar sua imagem.

4 Qual a diferença entre construir imagem e executar container?

O docker build processa o Dockerfile e gera uma imagem com os arquivos. O docker run cria e inicia um container a partir dela. Uma imagem pode gerar vários containers. Construir v2 não atualiza o container antigo automaticamente.
