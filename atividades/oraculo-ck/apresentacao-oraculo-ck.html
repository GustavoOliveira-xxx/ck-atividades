01O que foi pedido

A PROPOSTA

Construir uma interface web que se comunique com uma API de Inteligência Artificial, usando somente tecnologias de front-end. Estes foram os requisitos — e é por eles que vamos passar nos próximos slides.

Aplicação

  • Usuário insere um dado e recebe resposta da IA
  • Indicação visual de carregando
  • Tratamento de erro visível
  • Layout responsivo: desktop e celular

Requisitos técnicos

  • HTML5 semântico
  • CSS3 com Flexbox e Grid
  • JS moderno: arrow functions, template literals, destructuring
  • Código em arquivos separados

Documentação

  • Arquitetura com diagrama de blocos
  • Stack tecnológico justificado
  • Manual de uso e da chave de API
  • Plano de recuperação
Sem backend, sem servidor e sem banco de dados. A comunicação com a IA acontece direto do navegador, com fetch e async/await. Restrição central do projeto

O que zera a nota

  • Entregar sem documentação técnica
  • Não conseguir explicar o próprio código
02Escolha do tema

DICAS DE JOGOS MOBILE

Dos seis temas sugeridos, escolhemos o sexto. A decisão não foi por gosto — foi porque ele resolve três problemas de projeto de uma vez só.

1. Entrada estruturada

Jogo, tipo de conselho e nível são escolhas, não texto livre. Isso torna o prompt previsível e a resposta consistente — dá para demonstrar sem depender de sorte.

2. A IA agrega de verdade

É um domínio que muda toda temporada. Uma lista fixa de dicas envelhece; um modelo generativo responde à pergunta específica de quem está jogando.

3. Casa com a identidade CK

A nova logo da Conscious Knowledge é um mascote de esports — um mago encapuzado com um cajado. O produto virou o Oráculo: você consulta, ele responde.

04Diagrama de blocos

A ARQUITETURA

Quatro blocos e nenhum servidor no meio. O navegador é, ao mesmo tempo, a interface e o cliente HTTP que fala com a API de IA.

Usuário

Escolhe jogo, tipo e nível; escreve a pergunta e envia o formulário.

submit

Frontend

Valida os campos, monta o prompt e dispara a requisição HTTP.

fetch() + async/await

API de IA

O modelo generativo processa o prompt e devolve o texto dentro de um JSON.

generateContent

Resposta

O front lê o JSON, formata o texto e pinta o painel — ou o erro tratado.

render()
↩ o mesmo caminho de volta: JSON → parser → HTML seguro → painel · nada é gravado fora do navegador

Onde fica a chave

No localStorage do navegador de quem usa. Ela vai no cabeçalho x-goog-api-key, nunca na URL — assim não aparece em histórico nem em log de servidor.

O custo dessa escolha

Ser client-side significa que a chave está no navegador do usuário. É aceitável num trabalho escolar; em produção, a chamada iria por um backend próprio.

O que ganhamos

Zero infraestrutura: a aplicação é um conjunto de arquivos estáticos. Abre com dois cliques, publica no GitHub Pages e não tem o que cair.

05Organização do código

ARQUIVOS SEPARADOS

Nada de um HTML gigante. Cada arquivo tem uma responsabilidade só — e é isso que permite que seis pessoas trabalhem sem pisar no código uma da outra.

Árvore do projeto

oraculo-ck/ ├── index.html estrutura semântica ├── css/ │ ├── base.css tokens e reset │ ├── layout.css grid das seções │ ├── componentes.css peças da interface │ └── animacoes.css keyframes e reveals ├── js/ │ ├── config.js catálogo e endpoint │ ├── armazenamento.jslocalStorage │ ├── prompt.js monta o prompt │ ├── api.js fetch e erros │ ├── cena.js fundo em canvas │ ├── ui.js desenha a tela │ └── app.js liga tudo └── assets/

A regra que seguimos

  • ui.js não sabe o que é uma API — só recebe dados e pinta
  • api.js não sabe o que é um botão — só fala HTTP
  • app.js é o único que conhece os dois

Trocar o Gemini pelo OpenAI mexeria em um arquivo só.

Por que não módulos ES6?

import/export exigem um servidor HTTP: abrindo por file://, o navegador bloqueia por CORS. Como a apresentação precisa funcionar em qualquer máquina da escola, usamos scripts clássicos com defer e um namespace CK. Foi uma decisão de robustez, não de desconhecimento.

07js/api.js · o coração do projeto

A CHAMADA À API

Clique em cada linha à direita para ver o que ela faz. Esta é a parte que todo integrante precisa saber explicar.

js/api.js — chamarGemini()
// 1. controlador para poder abortar a requisição
const controlador = new AbortController();
const relogio = setTimeout(() => controlador.abort(), 30000);

// 2. o corpo no formato que o Gemini espera
const corpo = {
  contents: [{ role: "user", parts: [{ text: pergunta }] }],
  systemInstruction: { parts: [{ text: instrucao }] },
  generationConfig: { ...GERACAO }
};

// 3. a requisição — async/await, sem .then encadeado
const resposta = await fetch(`${BASE}/${modelo}:generateContent`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-goog-api-key": chave
  },
  body: JSON.stringify(corpo),
  signal: controlador.signal
});

// 4. fetch só rejeita em falha de rede: 4xx/5xx passam
if (!resposta.ok) {
  const { error } = await resposta.json().catch(() => ({}));
  throw traduzirHttp(resposta.status, error?.message);
}

// 5. leitura defensiva do JSON aninhado
const { candidates } = await resposta.json();
const [primeiro] = candidates ?? [];
return primeiro?.content?.parts?.[0]?.text ?? "";
08js/prompt.js

ENGENHARIA DE PROMPT

A qualidade da resposta não vem só do modelo — vem do que a gente pergunta. Separamos isso da camada de rede de propósito: dá para mudar a personalidade da IA sem tocar em uma linha de fetch.

a instrução de sistema (resumida)
Você é o Oráculo CK, assistente de jogos mobile
do grupo Conscious Knowledge.
Responda SEMPRE em português do Brasil.

Formato obrigatório da resposta:
1. Um parágrafo curto de resumo (máx. 2 frases).
2. De 2 a 4 blocos, cada um com '## ' e título curto.
3. Em cada bloco, de 2 a 4 itens começando com '- '.
4. Uma última linha com '> ' e o conselho principal.

Regras:
- Nada de "claro!" ou "com certeza!" — comece pelo conteúdo.
- Seja específico: cite nomes, números e situações.
- Se o meta pode ter mudado, diga isso em vez de inventar.
- Nunca sugira trapaça, script, hack ou conta pirata.
- Não recomende gastar dinheiro real como 1ª solução.
- Limite a resposta a ~300 palavras.
o prompt do usuário, montado pela interface
Jogo: Clash Royale
Tipo de conselho: Como counterar — foque em como
  responder a uma composição que está dando trabalho.
Nível do jogador: Intermediário (já joga com regularidade).

Pergunta: como counterar deck de ciclo rápido?

Por que o formato é imposto

  • O ## vira <h4>, o - vira <li>, o > vira o destaque final
  • Sem formato fixo, o parser teria que adivinhar
  • Antes de virar HTML, todo texto é escapado — a resposta da IA é tratada como conteúdo não confiável

10js/api.js · taxonomia de falhas

QUANDO DÁ ERRADO

Nenhum erro chega cru na tela. Toda falha vira um objeto com título, explicação e dica de ação — em português, para quem não sabe o que é um status HTTP.

SituaçãoO que o usuário lêA dica que damos
SEM_CHAVEChave da API não configuradaAbre o diálogo sozinho — ou oferece o modo demonstração.
HTTP 400Requisição recusadaConferir se a chave foi colada inteira, sem espaços.
HTTP 403Acesso negadoVerificar se a chave está ativa e sem restrição de origem.
HTTP 404Modelo não encontradoTenta o próximo modelo da fila automaticamente.
HTTP 429Limite de uso atingidoEsperar alguns minutos — ou seguir no modo demonstração.
HTTP 5xxServiço sobrecarregadoÉ passageiro: repetir a consulta em alguns segundos.
TEMPO_ESGOTADOA resposta demorou demaisConexão lenta: tentar de novo ou encurtar a pergunta.
SEM_CONEXAONão foi possível alcançar a APIFalta de internet, firewall da escola ou bloqueio de CORS.
BLOQUEADO_*Pergunta bloqueada pelo filtroReescrever a pergunta com outras palavras.
CANCELADOConsulta canceladaFoi o próprio usuário: é só consultar de novo.

Recuperação automática

Um 404 não vira erro na cara do usuário: a fila de modelos tenta o próximo sozinha. Só se todos falharem é que a mensagem aparece.

Antes de gastar requisição

Jogo não escolhido ou pergunta com menos de 6 caracteres nem chegam a chamar a API — a validação corta antes e avisa no rodapé.

Como testamos

Simulamos cada status pelo navegador e conferimos título, código e dica. Os 26 casos de contrato e de erro passaram.

  • <noscript> explica o que houve se o JS estiver desligado
12Honestidade técnica

DESAFIOS E PLANO

O que deu trabalho, o que ainda não está pronto e o que faríamos com mais tempo.

O que deu trabalho

  • fetch não rejeita em 4xx. Nossos primeiros erros passavam batido; só descobrimos testando com chave errada
  • O atributo hidden perdia para o display:grid. Os quatro estados apareciam juntos
  • Resposta em formato variável. Resolvido impondo o formato pela systemInstruction
  • Rolagem horizontal no celular, causada pelos elementos de fundo

O que ainda falta

  • A chave fica exposta no navegador — limitação assumida do modelo client-side
  • Sem streaming: a resposta aparece de uma vez, não palavra a palavra
  • Sem conversa em várias rodadas — cada consulta é independente
  • Testes são manuais e por script, não automatizados em CI

Plano de recuperação

  • Curto prazo: streaming com streamGenerateContent e histórico de conversa
  • Médio: proxy simples (Cloud Function) para tirar a chave do navegador
  • Sempre: o modo demonstração garante a apresentação mesmo sem rede

Nenhum requisito da proposta ficou de fora — o que listamos acima são melhorias, não pendências.
